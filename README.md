# ComfyUI H3 自动导演

这是 MiniMax H3 的多片段自动生成节点。它支持按片段输入提示词和时长，使用多模态参考素材生成每段视频，保存中间视频与 AV latent，并在最后自动拼接完整视频。

## 安装

将本目录放到：

```text
ComfyUI/custom_nodes/ComfyUI-H3-Auto-Director
```

重启 ComfyUI。连续视频/音频上下文已内置：新版 ComfyUI 使用核心的 `MiniMaxH3AddGuide` 原生任意帧锚定；旧版 ComfyUI 会自动启用插件内置的 Motion Context 兼容层。因此不再必须安装 `ComfyUI-H3-Motion-Context`。多模态参考仍依赖 ComfyUI 中的 `MiniMaxH3ReferenceToVideo`、`VHS_LoadVideo`、核心 `LoadAudio` 和 `ResolutionSelector` 节点。

如果出现节点注册、采样、张量形状或音频异常，请先将 ComfyUI 更新到最新版本，并重启实际运行工作流的 ComfyUI 进程，再检查模型和外部节点版本是否兼容。

## H3 音频采样切换

插件内置 `H3 自动导演｜音频采样切换` 节点，不需要额外安装
`ComfyUI-MiniMax-H3-LegacySampling`。它提供两个实现：

- `ComfyUI v0.31.0版本方法`：使用 AV 音频采样方法。
- `ComfyUI v0.30.0版本方法`：使用兼容旧版行为的 H3 音频采样方法。

旧工作流中保存的旧版本字符串仍会自动转换为对应的新选项。

`shift_video` 和 `shift_audio` 默认保持 `12.00 / 3.00`。音频采样切换节点有两个独立输出：

- `采样调度信息`：包含所选音频采样方法、视频偏移和音频偏移。连接到双采样节点的“音频采样方法”输入，模型主链仍直接接入双采样节点。
- `SIGMAS`：原版的基础 Sigma 端点输出，始终为有效 Tensor，可直接连接“插值扩展 Sigmas”。模型已连接时端点会采用已经应用视频/音频偏移后的 `sigma_max`；未连接模型时使用安全默认端点 `1.0 -> 0.0`，不会因空值报错。H3 的 `sigma_max` 通常为 `1.0`，使用“插值扩展 Sigmas”时请把其 `end_at_sigma` 设为 `1.0` 或更低；该核心节点默认值 `12.0` 虽不会报错，但不会在 H3 的端点之间插入中间步。此输出也可直接连接自动导演双采样的“一采/二采 Sigmas 调度”：插件会识别其为基础 Sigma，保留阶段节点自身的步数和调度器，并应用音视频偏移；同时可在双采样节点内开启同原版参数的 Sigma 扩展。若先经过外部“插值扩展 Sigmas”再接入双采样，则它是完整外部调度，步数以外部节点输出为准。

标准 `BasicGuider` / `BasicScheduler` 工作流不经过双采样节点时，在模型链后接 `H3 自动导演｜应用音频采样配置`，再把“采样调度信息”接入它。
该节点不提供、计算或输出采样步数、调度器或降噪。双采样节点内置一采、二采各自的“插值扩展 Sigmas”选项，其 `steps`、`start_at_sigma`、`end_at_sigma` 与 `spacing` 的定义和 ComfyUI 原版 `ExtendIntermediateSigmas` 完全一致：先按阶段步数生成基础调度，再在选定区间插值。因此一采设为 20 步时，20 步仍是基础调度；关闭内置扩展即实际执行 20 步。只有把外部或扩展后的完整 `SIGMAS` 明确接入双采样的一采/二采 Sigma 输入时，才会覆盖对应阶段的调度；此时内置扩展不会再次处理外部调度。
节点名称为“音频采样切换”，两个模式只改变 H3 音频采样时间尺度，视频 `shift_video` 仍由同一节点控制。双采样会把同一份配置分别应用到一采和二采模型；二采模型未连接时仍复用一采模型。模型主链不应再串联核心 `ModelSamplingMiniMaxH3` 或另一个 Legacy 节点。工作流文件不会因安装插件而自动修改。

音频上下文接续由片段计划中的“继续音频”“音频重生成”和运动上下文节点的“使用音频上下文”共同决定。正常接续时，插件从上一段缓存 latent 的尾部提取音频上下文，并按 H3 的 40 Hz latent 时间轴传入下一段；不要把普通音频参考误接到上下文缓存输入。插件会在每次采样前丢弃跨片段缓存的旧 `PackedLayout`，按当前视频/音频 latent 重新建立布局，避免不同片段时长造成行数错位。

### 音频采样方法的选择

- 使用 ComfyUI v0.31.x 或更新核心，并且启用视频+音频上下文接续、音频参考或视频音轨参考时，选择
  `ComfyUI v0.31.0版本方法`。该模式使用当前核心的 AV 音频采样和原生 H3 条件布局。
- 需要复现 ComfyUI v0.30.0 的音频采样行为，或只生成独立片段、只使用画面上下文时，选择
  `ComfyUI v0.30.0版本方法`。它只切换采样时间尺度，不会把当前 ComfyUI 核心降级为 v0.30.0。
- 两种模式不要同时连接，也不要再串联核心的 `ModelSamplingMiniMaxH3` 或外部
  `ComfyUI-MiniMax-H3-LegacySampling` 节点。切换后需要重新执行当前工作流；修改节点代码后需要重启实际运行工作流的 ComfyUI 进程。

### 已知的旧版方法音频上下文错误

在新版 ComfyUI 核心中选择 `ComfyUI v0.30.0版本方法`，并同时开启视频上下文和音频上下文时，部分 H3 latent
形状会触发以下错误：

```text
RuntimeError: The expanded size of the tensor (414) must match the existing size (340)
```

该错误发生在 H3 的 `PackedLayout` 音频条件布局，与 ffmpeg、随机种子、文本编码器或模型文件损坏无关。原因是旧版音频采样包装器与新版原生音频上下文布局对同一段 latent 的音频步数计算不一致。

临时规避方式：

1. 需要音视频上下文接续时，切换为 `ComfyUI v0.31.0版本方法`；或
2. 保持 v0.30 方法，但关闭发生错误片段的“音频上下文接续”，视频上下文可以继续使用。

v0.30 方法在独立片段、普通多模态参考和仅视频上下文场景仍可使用。v0.30 和 v0.31 两条采样路径现在都会在每次 H3 前向前丢弃跨片段缓存的 `PackedLayout`，并按当前 keyframe/ref latent 重建条件列表，避免不同片段的音频长度串用。v0.30 路径如果仍遇到音频布局错误，会自动移除自动导演注入的音频上下文、保留视频上下文并重试；原生 v0.31 路径则保留音频上下文并使用刷新后的布局。插件会在旧版核心上启用内置的 Motion Context 兼容层；该兼容层不等于把新版核心的 AV 音频布局强行改回旧版。如果仍出现新的布局尺寸错误，请提供重启后的完整 traceback，并检查是否串联了外部 LegacySampling 节点。

## 模型补丁与兼容性

自动导演不内置 LoRA 或其他外部性能补丁。需要使用这些外部节点时，请按对应项目当前版本的
说明自行连接；本仓库不规定特定外部性能补丁、连接顺序或二选一配置。遇到节点注册、采样、张量形状
或音频异常时，请先将 ComfyUI 更新到最新版本并重启实际运行工作流的进程，再确认 H3 模型、VAE、
参考素材节点与外部补丁来自兼容版本。

可选的 H3 Turbo 加速 LoRA 可从
[lightx2v/Minimax-h3-Turbo](https://huggingface.co/lightx2v/Minimax-h3-Turbo/tree/main)
下载，并通过标准 `LoraLoaderModelOnly` 接到模型链。Turbo LoRA 可能与带独立音频参考或视频音轨
参考的附加时间条件不兼容；出现张量形状错误时，请先更新 ComfyUI，再断开 Turbo LoRA 验证基础流程。

## 可选混合模型

示例工作流中的“`H3 自动导演｜多模态参考模型加载`”默认关闭“启用 H3 混合模型”，此时只加载 `Ref2VA`，与原工作流行为一致。开启后，节点以 `FL2VA` 为画面基础，并只从 `Ref2VA` 覆盖第 25 至 49 个 DiT Block 的 AdaLN 权重，以尝试兼顾多模态素材遵循与 FL2VA 的画面质量。

请使用同一量化系列、键集合一致的模型对。已验证本机 `*_pruned_int8_convrot.safetensors` 的 FL2VA/Ref2VA 可以配对；`*_pruned_w4a8_mixed.safetensors` 两文件的键集合不同，不能混合。开启混合会在工作流开始时卸载已加载模型以释放内存，因此不要把此节点插入自动接续流程中间。该功能属于实验性模型合并，建议用相同提示词、素材、种子和采样参数分别对比纯 Ref2VA 与混合结果。

“MiniMax H3 Experimental Motion Transfer”中的“动作迁移模型加载”也包含相同开关，默认关闭。动作迁移的参考视频、图片、音频传入方式和后续采样链均不变；仅替换扩散模型权重来源。

## 工作流接法

工作流 `MiniMax H3 Auto Director.json` 已提供一份可直接打开的连线示例：

```text
项目计划 -> 片段设置 -> H3 多模态参考生成
                       -> 自动导演上下文 -> 引导器/采样器/解码
解码后的视频与音频 + AV latent -> 保存中间片段
保存的视频 -> 自动控制器 -> 下一段或最终拼接视频
```

分辨率由 `ResolutionSelector` 统一输出宽、高并连接到 H3 参考生成节点。片段设置节点与项目计划直接连接到“MiniMax H3 多模态参考生成｜提示词缓存”；该节点会按当前片段自动加载正确的图片、视频、视频音频和独立音频参考素材。片段设置节点的“片段节点ID”直接连接到自动控制器，不需要手动填写 ID。

`MiniMax H3 Experimental Motion Transfer.json` 与 `MiniMax H3 Experimental TTS.json` 均为实验性工作流，仅用于探索动作迁移和 H3 音频生成编排。不保证模型版本兼容性、生成效果、长序列稳定性或生产可用性；请先用短片段和基础模型验证，再用于实际项目。

## 片段与参考素材

点击“编辑片段”后，可增删片段，逐段填写提示词和时长（4～15 秒），并为每段添加图片、视频或音频参考。项目计划中的“全局统一参考素材”开启时，所有片段使用第一段的参考集合；关闭时，每段使用自己的集合。编辑器提供“将第 1 段参考素材应用到全部”按钮。

编辑器还提供“片段数量”数字输入，可一次性增删片段；“直接输入片段配置 JSON”可粘贴数组后应用；“统一片段秒数”会把所有片段的 `duration` 设置为相同值，点击“应用到全部片段”后立即刷新每个片段的时长输入框。

每个视频参考卡片都会显示“传递视频音频”开关，默认保持开启；关闭后只传递视频画面。插件会自动检测音轨，视频没有音轨、音轨检测失败或音轨损坏时仍保留该开关，并自动降级为仅传递画面，不会因 ffmpeg 报“Output file does not contain any stream”而中止任务。存在可用音轨的视频会按 H3 的实际顺序占用 `<Audio 1>`、`<Audio 2>` 等提示词标签，独立音频标签会自动顺延。

上传设置包含“使用默认打开路径”和“文件选择方式”。默认打开路径开启时，Python 原生模式使用各类型输入框中的目录，浏览器模式使用已授权的目录句柄；关闭时两种模式都使用各自系统记忆的上次目录。Python 原生模式由 ComfyUI 所在机器打开 Windows 原生文件对话框，所有浏览器都可使用。文件会固定复制到 `input/h3_refs/images`、`input/h3_refs/videos` 和 `input/h3_refs/audio`。按钮会启用 Windows Per-Monitor DPI 感知，适配高分辨率和多显示器缩放。

项目计划中的“自动连续生成”控制是否在片段保存后自动排队下一段；“接续模式”控制下一段是否按 `segment_index` 读取上一段的视频和 AV latent 上下文。接续模式开启时，片段节点会读取当前序号对应的提示词、时长和参考素材，并由上下文读取节点加载前一段缓存；关闭时仍可自动生成多段，但每段按独立场景生成，不要求前一段缓存。

`segment_index` 是上下文序号：设为 `0` 生成第 1 段且不读取缓存；设为 `3` 时读取 `clip_00003.mp4` 与对应 latent，并生成第 4 段提示词和参考素材。自动控制器会在保存第 N 段后把下一次运行的上下文序号设为 N。

## 提示词向量缓存与随机种子

项目计划中的“一次性缓存提示词向量”默认关闭。开启后，第一次执行会对项目全部片段编码完整的多模态 conditioning，并保存在当前 ComfyUI 进程内存中；之后自动生成各段时会直接复用对应片段的 conditioning，不再重复调用 33B 文本编码器。缓存不是只有纯文本 token，也包含图片、视频和音频参考素材编码后的 H3 conditioning。

需要跨 ComfyUI 重启复用时，可开启“缓存提示词向量到硬盘”。关闭“一次性缓存提示词向量”时，硬盘开关只为当前正在生成的片段读取或保存向量，不会预编码全部片段；同时开启两个开关时，首次运行才会预编码所有当前可用片段。向量保存在当前项目的 `cache/prompt_embeddings/segment_00001.pt` 等文件，`manifest.json` 记录项目参数、分辨率、参考图缩放模式、编码器类型、每段提示词和参考素材文件的大小/修改时间。下一次执行会逐段比对清单，匹配则加载 CPU 向量，只有不匹配的片段重新编码。

随机种子不会影响文本编码器缓存，也不需要清空缓存。种子只在 `RandomNoise` 和采样器阶段决定初始噪声，修改种子会得到不同的视频/音频采样结果，但仍复用相同提示词与参考素材向量。提示词、参考素材、分辨率、参考图缩放策略、上下文长度或 CLIP/VAE/audio VAE 改变时会使用新的缓存。内存缓存最多保留 2 个项目；硬盘缓存由项目目录独立保存。

提示词按 Ref2VA 多模态格式组织，参考编号从 `1` 开始，例如 `<Picture 1>`、`<Video 1>`、`<Audio 1>`，并分别描述主体、动作、镜头和声音。每段参考素材总数最多 12 个，其中图片最多 9 个、视频最多 3 个、独立音频最多 3 个；上传界面和计划节点都会拒绝超过上限的配置。

## 音频重新生成

勾选某段的“重新生成音频”后，该段仍可继承上一段视频画面，但不会继承上一段音频上下文。该段产生的新音频会成为下一段的起始音频。可以在多个片段设置重新生成点。

## 断点续接

`H3 自动导演｜断点续接` 默认关闭。开启后，手动填写匹配的 `.safetensors` AV latent 路径和视频路径；节点不会自动选择最新缓存。新项目会保存到 `output/h3_project/<项目文件夹名称>/`，总文件夹包含 `json/`（项目与状态 JSON）、`cache/`（AV latent）、`clips/`（中间视频）和 `final/`（最终视频）。保存节点的“输出文件名”默认留空，实际使用 `H3`，例如 `clips/H3_00001.mp4`、`cache/H3_00001.safetensors` 和 `final/H3.mp4`。旧版 `clips/clip_00001.mp4` 与 `latents/clip_00001.safetensors` 布局仍可读取。

## 保存输出

`H3 自动导演｜保存中间片段` 必须接收采样器输出的未裁剪 AV latent，以及运动上下文裁剪后的视频帧和音频。“输出文件名”只改变文件名，不改变项目目录；留空使用 `H3`。最终拼接节点同样使用“输出文件名”，留空生成 `final/H3.mp4`。接续读取始终限定在项目计划对应的总文件夹内，按片段序号查找视频和 latent，避免不同项目互相读取。当片段编码参数不完全一致时会自动回退到重新编码拼接。

保存节点的“自动裁剪上下文”开关默认关闭。关闭时保存完整解码时间轴，便于检查跳变和上下文重叠。项目计划编辑器新增“自动裁剪上下文帧数”：设为 `0` 时按当前上下文长度自动计算，设为大于 `0` 时使用指定帧数并自动启用裁剪；显式连接保存节点的 `trim_frames` 或运动上下文裁剪输出仍可覆盖该默认值。该设置只影响保存的画面/音频，不改变采样过程；帧数过大而达到视频总帧数时会被节点拒绝，以避免保存空片段。

“上下文色彩校正”位于保存中间片段节点，默认关闭。选择“匹配首段”后，第 1 段作为固定色彩锚点；选择“匹配上段”后，每段使用紧邻的上一段作为色彩锚点。第 2 段及以后在保存前使用锚点尾帧的保守 RGB 统计进行一次性校正；音频、FPS 和 AV latent 不变。校色只作用于 `clips/` 中的最终显示视频，下一段上下文仍读取未校色的 `context/` 原始视频，避免显示层校色污染 H3 条件。“匹配上段”可能随连续片段逐步改变色调，“匹配首段”更适合固定场景。若锚点缓存不存在，该段会记录警告并保留原视频。

色彩校正参数建议从以下组合开始：连续同场景使用“匹配上段”、场景切换保护开启、场景切换阈值 `0.20`、校色强度 `0.50`、残余漂移强度 `0.15`。校色仍不足时，将校色强度提高到 `0.70~0.75`；只有确认场景没有真实切换而校色经常被跳过时，才把场景切换阈值提高到 `0.25~0.30`。残余漂移强度通常保持 `0.10~0.20`，超过 `0.30` 可能引入逐帧闪烁。第一段不会执行匹配，这是预期行为。自动裁剪上下文与色彩校正相互独立；自动裁剪开启会删除上下文前缀并可能让上下文结束处的原始色彩漂移更早出现在片段开头。

音频封装和最终拼接会自动查找 `PATH` 中的 ffmpeg、`FFMPEG_PATH` 环境变量、`imageio-ffmpeg` 自带程序以及 ComfyUI 常见安装目录，不要求必须从启动终端的 `PATH` 继承 ffmpeg。

更新插件代码后必须重启实际执行工作流的 ComfyUI 进程；如果同时运行了多个端口，请重启工作流当前连接的那个端口对应的进程。

## 验证

## 快速开始

1. 将本仓库放入 `ComfyUI/custom_nodes/ComfyUI-H3-Auto-Director`，安装 H3 模型、VAE、CLIP、VideoHelperSuite、ResolutionSelector 和 ffmpeg，然后重启 ComfyUI。
2. 导入 `example_workflows/MiniMax H3 Auto Director.json`，检查模型、VAE、CLIP 和分辨率选择器。动作迁移与 TTS 工作流属于实验功能，分别导入对应的 `example_workflows/MiniMax H3 Experimental *.json`。
3. 在项目计划节点填写项目文件夹、片段 JSON、自动连续生成、接续模式和提示词缓存；首次运行使用 `segment_index=0`。
4. 确认以下主链路已经连接：

```text
项目计划 -> 片段设置 -> 多模态参考生成 -> 运动上下文
                                  -> 引导器 / 采样器 -> VAE 解码
                                  -> 保存中间片段 -> 自动控制器 / 最终拼接
```

片段设置的 `参考素材` 必须连接到多模态参考生成的 `参考素材 JSON`，这样每段会按自身编号读取提示词和素材，不需要手动填写 `segment_node_id`。

## 续接、缓存与输出

- `统一参考集` 开启时所有片段使用第 1 段素材；关闭时只使用各自的 `references`。编辑器的“将第 1 段参考素材应用到全部”会显式复制并重新检查数量上限。
- `segment_index=0` 生成第 1 段；设置为 `3` 时读取第 3 段缓存并生成第 4 段。自动控制器会在保存第 N 段后排队下一段。
- 断点续接默认关闭。开启后手动选择匹配的 latent 和视频，并确认项目文件夹名称。新项目目录为：

```text
output/h3_project/<项目文件夹名称>/{json,cache,clips,final}/
```

- 开启“一次性缓存提示词向量”后，所有片段的多模态 conditioning 只编码一次；开启“缓存提示词向量到硬盘”后可跨重启保存并按清单逐段复用。关闭一次性缓存时不会触发全片段预编码，硬盘缓存只处理当前片段；两个开关仍可独立设置。清单 JSON 会按片段提示词、素材文件指纹、分辨率和编码器配置决定是否重新编码。随机种子不会使缓存失效。
- “重新生成音频”只关闭该段的音频上下文，新音频会成为下一段的起始音频。保存节点接收 AV latent、解码画面和音频；`fps` 使用数字 `24`。
- 输出文件名留空时使用 `H3`。中间视频、latent 和最终视频始终限制在项目目录中；最终拼接成功后才会按开关清理显存。找不到 ffmpeg 时设置 `FFMPEG_PATH` 或安装 `imageio-ffmpeg`。
- 音频采样建议在 ComfyUI v0.31.x 选择“ComfyUI v0.31.0版本方法”，视频/音频调度偏移保持 `12 / 3`。v0.30 兼容方法只用于复现旧版行为；在新版核心同时开启音频上下文时可能出现布局尺寸错误或音频质量异常。若生成音频是杂音，先确认只连接一个音频采样切换节点、没有再串联外部 LegacySampling/`ModelSamplingMiniMaxH3`，且音频 VAE 使用 `minimax_h3_audio_vae_fp32.safetensors`。插件会记录实际采样模式和偏移，并在解码、双采样重组、缓存保存和 WAV 写入时统一检查 `[B,32,2,T]`、`[B,C,L]`、声道数、有限值和 32 kHz 采样率；日志若显示非 32 kHz 或非 32 通道，应先更换音频 VAE。

双采样节点的“最终仅使用一采音频”开启后，最终 AV latent、保存视频音轨以及一采/二采上下文缓存均使用一采音频；保存节点会优先采用双采样节点附带的一采音频数据。

## JSON 提示词技能

仓库包含可供其他模型直接调用的技能：`skills/h3-auto-director-json/SKILL.md`。它会输出能直接粘贴到项目计划节点“片段配置”的 JSON 数组；默认不生成或虚构任何图片、视频、音频素材，每段的 `references` 都为空数组。技能同时覆盖长视频与 TTS：TTS 使用同样的六段式结构，但会围绕音色、语言、台词、发音、停顿、情绪、环境声和音乐写完整音频时间线；可选 `audio_filename` 只能是唯一的 `.wav` 文件名，不能是目录路径。

技能强制每个片段使用 MiniMax H3 Ref2VA 官方六段式描述：`subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape` 和 `non_diegetic_music`。除非用户明确要求极简动作，否则每段都会包含完整镜头、动作过程、环境、镜头运动、声音与收束姿势，而不是只输出“跑步”等简略动作标签。

素材文件路径、H3 素材编号和素材作用说明是三个独立信息：路径只决定插件是否能载入文件，可以留空；用户声明的 `<Picture N>`、`<Video N>`、`<Audio N>` 编号及其作用说明必须写入适用片段的提示词，不能用文件名或 `<Subject N>` 替代。只有提供了准确本地路径的素材才写入 `references`；只提供编号和作用时仍保留 `references: []`。模型无法直接读取素材、或用户没有提供具体素材内容时，技能只会按用户说明写基础作用，不会虚构人物外貌、服装、场景、动作、音色、音乐或环境声。除非用户明确要求，具有图片参考的人物不额外描写外貌与服装；音频及带音轨的视频同样只描述用户明确要求的作用。

## 保存与排错

- 中间片段节点必须接收 AV latent、H3 AV 解码节点输出的画面和对应音频；新版原生 Guide 会把上一段尾部窗口固定在本段开头，保存节点会自动裁掉默认的 22 帧上下文前导（也可连接 Motion Context 的“裁剪帧数”输出覆盖），避免拼接重复。
- 项目目录为 `output/h3_project/<项目名>/`，其中 `context/` 保存未经最终校色的上下文源，`clips/` 保存校色后的中间片段，`cache/` 保存 AV latent，`final/` 保存最终拼接视频。接续模式只读取 `context/`，旧项目没有该目录时自动回退到 `clips/`。
- 自动导演上下文节点默认优先从缓存 AV latent 尾部直取视频 latent；双采样项目的一采和二采都会优先使用上一段最终二采视频/latent 作为上下文，并按当前采样阶段的空间尺寸自动适配，只有最终二采缓存不存在时才回退到旧的一采缓存。新版 ComfyUI 通过原生 Guide 在目标时间轴写入视频与音频锚点；旧版自动使用插件内置兼容层。该选项可在节点的“使用视频 latent”输入中关闭。
- “拼接最终视频”节点默认只在所有片段存在、最终文件写入成功且大小大于 0 后清理显存；中间片段保存、拼接失败或暂停时不会清理。可通过“最终视频完成后清理显存”关闭。
- `fps` 使用数字 `24`，不要填入文本。
- 输出文件名只控制文件名，不改变项目目录；留空使用 `H3`。
- 找不到 ffmpeg 时设置 `FFMPEG_PATH`，或安装 `imageio-ffmpeg`。
- 如果日志出现 `VHS failed to extract audio`、`Output file does not contain any stream`，通常表示参考视频没有音频流，而不是视频画面损坏。当前插件会先检查视频流布局：无音轨或音轨不可读时保留视频画面、将视频音频置空并继续生成；若确实需要视频音频，请换用包含可解码音轨的文件并确认“传递视频音频”已开启。
- `3 vs 2` 的 tensor 错误通常来自 Turbo LoRA 与音频参考时间条件不兼容，先断开 Turbo LoRA 判断基础 H3 是否正常。

## 实验工作流说明

### 双采样 latent 学习型放大与分阶段模型

双阶段采样节点新增 `H3 Latent 学习型放大`。它直接在 H3 视频 latent 的空间维运行上游
[Comfyui_Minimax_h3_latent_Upscaler](https://github.com/LBH-123-AI/Comfyui_Minimax_h3_latent_Upscaler)
的 3D 网络，保持时间轴和音频 latent 不变，避免一采视频的 VAE 解码、像素放大、再编码损失。
模型文件放在 `ComfyUI/models/latent_upscale_models/`；当前本地示例使用
`minimax_h3_latent_upscaler_3d_fp32.pth`。普通插值、普通放大模型和 RTX 路径仍保留。

`H3 自动导演｜一采/二采模型加载` 可分别选择两次采样的 Ref2VA 模型，并可分别开启
H3 混合模型：开启后用对应的 FL2VA 作为画面基础、Ref2VA 作为多模态覆盖；关闭时只加载
Ref2VA。需要 LoRA 时请在该节点输出后连接标准 ComfyUI `LoraLoaderModelOnly`，再把处理后的
模型连接到双采样节点对应阶段；节点本身不再加载或管理 LoRA。该模型加载节点只输出一采/二采
MODEL，不包含 Sigma 调度输入或输出；旧工作流载入时插件会自动移除遗留端口。双采样节点的“一采模型”和
“二采模型”都是可选输入，二采输入未连接时会自动复用一采模型，因此只使用一套模型时无需
额外复制模型链。
新版采样预览是可选开关，依赖当前 ComfyUI 的 `latent_preview` 接口；旧版没有该接口时会自动
回退为无预览采样，不影响生成。

项目计划的每个图片、视频、音频参考卡片都有“插入时间（秒 + 帧）”。两项均为 `0` 时素材只
作为普通多模态参考；任一项非零时，插件在新版 ComfyUI 中追加对应时间点的 `MiniMaxH3AddGuide`
（视频音频按该素材的“传递音频”开关决定）。旧版核心没有 Guide 接口时仍保留普通参考，不会
把素材静默丢弃。帧位置按 24 fps 计算，秒和帧相加后作为目标帧索引。

该放大模型和按时间插入 Guide 都属于实验性功能。推荐先用两段短视频、关闭二采上下文验证
边界帧和显存占用，再用于长项目。

新增 `H3 自动导演｜动作迁移项目计划`，用于把一个参考动作视频按设定秒数切成多个 H3 片段。点击节点中的“编辑动作迁移计划”，即可集中上传参考动作视频、主体图片和独立音频，并设置统一提示词、每段秒数、音频接续、重新生成音频片段、上段视频参考、最终音频来源、一次性提示词缓存和自动连续生成。节点会按 24 fps 计算段数，最后一段使用剩余时长；参考视频窗口不足 H3 的 `17k+5` 帧网格时只在参考编码侧重复尾帧，不会修改该段的请求时长。提示词在所有片段复用，重新生成音频和上段视频参考使用 1-based 片段编号，支持中文逗号、英文逗号混用。

动作迁移从第 2 段开始默认启用上一段生成画面的视频上下文接续，同时继续传入当前时间窗的参考动作视频。若某段编号填入“使用上段视频参考片段”，该段会关闭视频上下文，改为把上段生成视频作为额外的无音频多模态视频参考；音频上下文仍按“开启音频上下文接续”和“重新生成音频片段”独立决定。

`MiniMax H3 多模态参考生成｜提示词缓存` 提供两种图片参考尺寸模式：开启“使用预设”后通过“预设选项（match/max）”选择自动尺寸；关闭“使用预设”会同步开启“使用手动设置”，并显示“参考图最短边”。关闭手动模式时会同步恢复预设模式，两个模式不会同时关闭。手动输入会立即对齐并显示为最近的 32 倍数，后端执行时也会再次校正。图片只缩小不放大，视频参考仍使用 H3 自己的约 768 短边/面积上限适配规则。

`H3 视频迁移｜按策略解码` 会始终解码画面；“仅不解码 H3 音频（仍联合采样）”开启时不调用 H3 音频 VAE。最终音频来源可以选择 H3 生成音频，或参考视频的完整音频；选择后者时最终拼接节点会在所有片段拼接完成后一次性替换为原视频音轨，避免逐片段截取造成累计误差；它与“传递参考视频音频”相互独立。

新增 `H3 自动导演｜TTS 项目计划` 和 `H3 TTS｜仅解码音频`。TTS 计划支持图片、视频、音频参考素材，其中图片和视频分组默认折叠，音频分组默认展开；每段可设置独立 WAV 文件名、独立关闭音频接续；视频参考素材下方的“传递音频”开关也按视频单独设置，关闭后只传递视频画面。新增片段或刷新列表时会保留各段参考区域的展开/折叠状态，底部操作栏固定在编辑器底部。旧版全局参考素材字段仍可读取，但已从新版节点界面移除。每段 latent 缓存仍按项目固定编号保存。`拼接最终长音频` 可关闭，关闭时只保留各段 WAV；开启时由 `H3 TTS｜拼接最终音频` 生成一个长 WAV。实验示例为 `example_workflows/MiniMax H3 Experimental TTS.json`。H3 核心节点的宽高接口下限为 `32`，且必须是 32 的倍数；因此该 TTS 实验工作流使用 `32 x 32`，只作为不解码画面的音频实验占位，不代表推荐的视频生成画布。

`MiniMax H3 Experimental Motion Transfer.json` 已简化为动作迁移项目计划、动作迁移模型加载、片段设置、迁移条件、双阶段联合采样、解码保存和自动拼接。`H3 自动导演｜双阶段采样` 会先以低分辨率采样，再在像素空间放大并重新编码视频 latent，保留第一阶段音频 latent 后以较低重绘幅度进行第二次联合采样；放大方式支持普通插值、普通放大模型、RTX Video Super Resolution，以及 RTX 失败后回退普通模型/插值。

双阶段采样推荐从第一阶段 6 步、降噪 1.0，第二阶段 8 步、降噪 0.65 开始。动作迁移与长视频自动导演示例均使用同一 `H3 自动导演｜双采样分辨率` 节点：可用“使用预设比例”或“使用自定义比例”两个开关选择模式；自定义模式输入 `宽,高`，同时支持中文逗号，例如 `2,3` 或 `2，3`。节点会实时预览两阶段对齐后的宽、高和实际 MP。两个开关同时打开时以自定义比例为准，同时关闭时回退到 16:9。

二采的“二采使用上下文”目前定义为实验性功能，现阶段效果不可用，默认应保持关闭。开启时会尝试把上一段最终二采视频/音频的尾部窗口重新适配到二采目标 latent 尺寸后再注入，但目前不能保证接续、清晰度或稳定性；不会使用上一段一采结果。关闭时二采直接从已包含一采接续边界的 latent 开始。后续修复完成前，请勿将该选项用于正式生成。

视频上下文接续使用 H3 Guide 在当前片段时间轴的开头直接约束上一段尾部窗口，不会把上一段作为额外前缀写入本段，也不会默认裁剪本段开头。因此拼接时不会因插件重复保存上一段画面；边界处出现极短的相近姿态是模型为保持动作连续性生成的过渡，而非重复复制帧。此前实验性的“二采局部时间遮罩”和“二采残差混合强度”已完全移除；关闭“二采使用上下文”时，第二阶段直接从已完成一采的 latent 开始，不再额外锁定或混合接缝。由于“二采使用上下文”当前仍是实验性且效果不可用的功能，现阶段不建议开启。

当第一阶段与第二阶段的目标分辨率对应到相同的 H3 latent 网格时，双采样节点会直接传递一采视频 latent，跳过像素放大和第二次视频 VAE 编码（节点预览仍只做一次解码）；音频 latent 也保持原样。只有空间网格不同才执行放大和视频 VAE 重编码。

双采样节点还提供“最终仅使用一采音频”。开启后第二阶段仍然细化画面，但最终 AV latent、保存视频音轨以及一采/二采上下文缓存均使用第一阶段的音频 latent，适合二采音频出现杂音或希望保持一采音频连续性的情况；保存节点会优先采用双采样节点附带的一采音频数据，关闭时使用二采生成的音频。
